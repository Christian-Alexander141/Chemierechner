Chemierechner

Softwaredokumentation: Aufbau, Bedienung und Erweiterung

Stand: 31.10.2026 Java 25 JavaFX 25.0.4 Lizenz: siehe LICENSE

1Überblick

Der Chemierechner ist eine Desktop-Anwendung in Java mit JavaFX-Oberfläche. Mit ihm lassen sich typische Rechnungen aus dem Chemieunterricht und Studium erledigen: Stoffmengen, Anteile, Partialdrücke, Titrationskurven. Außerdem gibt es einen AI-Modus, der Fragen an ein lokal laufendes Sprachmodell weitergibt.

Die Oberfläche ist so gebaut, dass neue Rechner ohne JavaFX-Kenntnisse ergänzt werden können: Jeder Rechner ist eine kleine Klasse, die nur beschreibt, welche Eingaben und Ergebnisse es gibt. Wie das aussieht, entscheidet das Grundgerüst im Paket gui.

Funktionen

BereichFunktion
FormelnPartialdruck, Masseanteil, Volumenanteil, molares Volumen, Stoffmenge, molare Masse
TitrationMesspunkte erfassen, in einer Tabelle bearbeiten, Titrationskurve wird automatisch gezeichnet
AI‑ModusChemische Fragen an ein lokales Sprachmodell über Ollama
KomfortKomma oder Punkt als Dezimaltrennzeichen, Enter startet die Berechnung, Ergebnis per Klick kopieren, verständliche Fehlermeldungen

2Installation & Start

Voraussetzungen

KomponenteVersionErwarteter Ort

VS Code (optional)aktuellmit „Extension Pack for Java“
Ollama (nur AI-Modus)aktuellläuft auf http://localhost:11434

JavaFX ist seit Java 11 nicht mehr Teil des JDK und muss separat heruntergeladen werden (gluonhq.com/products/javafx). Das SDK wird einfach entpackt; Pfade zu ihm stehen in .vscode/settings.json, .vscode/launch.json und run.sh. Liegt es woanders, müssen diese drei Stellen angepasst werden.

Für den AI-Modus muss zusätzlich das Modell installiert sein:

ollama pull cas/teuken-7b-q4km
ollama serve

Start in VS Code

  1. Den Repository-Ordner Chemierechner (oberste Ebene) in VS Code öffnen.
  2. Ansicht „Ausführen und Debuggen“ öffnen (Strg+Shift+D).
  3. Im Dropdown „Chemierechner - STARTEN“ wählen und F5 drücken.
Werden JavaFX-Importe rot markiert?

Dann hat VS Code die Einstellungen noch nicht übernommen: Strg+Shift+P → „Java: Clean Java Language Server Workspace“ → „Restart and delete“.

Start im Terminal

cd ~/Dokumente/Github/Chemierechner/Chemierechner
./run.sh

Das Skript löscht bin/, kompiliert alle Quellen neu, kopiert die Ressourcen (CSS, Icon, Textdateien) und startet anschließend gui.ChemierechnerApp.

3Bedienung

Links befindet sich die Seitenleiste mit allen Rechnern. Ein Klick wechselt die Ansicht; eingegebene Werte bleiben beim Wechseln erhalten.

Formel-Rechner

  • Werte in die Felder eingeben. Die Einheit steht rechts im Feld.
  • 0,5, 0.5 und 6,022e23 werden alle verstanden.
  • Berechnen klicken oder in einem Feld Enter drücken.
  • Ein Klick auf ein grünes Ergebnisfeld kopiert den Wert in die Zwischenablage.

Titration

  • Volumen und pH-Wert eingeben, dann „Messpunkt hinzufügen“ (oder Enter im pH-Feld).
  • Werte in der Tabelle per Doppelklick ändern.
  • Zeile löschen: auswählen und Entf drücken oder Rechtsklick → „Zeile löschen“.
  • Die Kurve aktualisiert sich nach jeder Änderung automatisch.

AI-Modus

  • Frage eingeben, „Senden“ oder Enter. Während das Modell antwortet, erscheint unten „Bitte warten …“ und die Buttons sind gesperrt.

5Architektur

Schichten

Das Programm ist in drei Schichten aufgeteilt. Jede Schicht kennt nur die darunterliegende. Dadurch bleibt die Fachlogik frei von Oberflächencode und lässt sich unabhängig testen.

Karten
Beschreiben die einzelnen Rechner: welche Eingaben, welche Ergebnisse, was beim Klick passiert. Kein JavaFX.
karten
↓ benutzt
GUI-Grundgerüst
Fenster, Seitenleiste, Layout, Bausteine, Fehleranzeige. Kapselt JavaFX vollständig.
gui
↓ Karten rufen zusätzlich auf
Fachlogik
Chemische Formeln, Datenhaltung, Netzwerkzugriff. Weiß nichts von der Oberfläche.
BerechnungenTitrationenAPIcallsKonstantenGroesen

Einzige Ausnahme von „nur nach unten“: gui.ChemierechnerApp holt sich beim Start die Liste der Karten aus karten.Karten. Diese eine Stelle verbindet beide Pakete.

Programmstart

ChemierechnerApp.main()→ JavaFX startet→ start(stage)→ Karten.alle()→ Konstruktoren der Karten bauen ihren Inhalt→ Seitenleiste + erste Karte anzeigen

Alle Karten werden beim Start einmal erzeugt und danach nur noch ein- und ausgeblendet. Deshalb bleiben Eingaben beim Wechseln erhalten. Wirft ein Karten-Konstruktor eine Exception, startet das Programm nicht; die Ursache steht dann in der Konsole.

Ereignisfluss bei einem Klick

Klick / Enter→ Karte.ausfuehren(aktion)→ alte Meldung ausblenden→ aktion.run()→ bei Exception: Meldung unten anzeigen

Jede Aktion, die über einen Button, Enter oder eine Tabellenänderung ausgelöst wird, läuft durch ausfuehren(). Dort werden alle Exceptions abgefangen. Die Karte selbst muss also kein try/catch schreiben. Details in Kapitel 10.

6GUI-Grundgerüst (gui)

Das Paket gui enthält alles, was mit JavaFX zu tun hat. Öffentlich (public bzw. protected) sind nur die Methoden, die Karten brauchen; JavaFX-Typen tauchen dort nirgends auf.

Abstrakte Basisklasse jeder Karte. Eine Unterklasse ruft im Konstruktor die folgenden Methoden auf; die Bausteine erscheinen in genau dieser Reihenfolge auf dem Bildschirm.

Layout-Regeln

  • Mehrere zahlenfeld()-Aufrufe direkt hintereinander landen zweispaltig nebeneinander.
  • Mehrere button()-Aufrufe direkt hintereinander landen in einer Reihe.
  • Alle anderen Bausteine nehmen die volle Breite ein und beenden eine laufende Feld- oder Button-Gruppe.
  • Der Inhalt ist maximal 920 px breit und wird zentriert; bei Bedarf erscheint ein Scrollbalken.

Klasse Formelkarte

Spezialisierung von Karte für das häufigste Muster: Zahlen eingeben → Berechnen → Ergebnis. Der Aufbau (Eingaberaster, Button, Ergebnisraster) wird schon im Konstruktor der Formelkarte angelegt. Deshalb ist die Reihenfolge von eingabe() und ergebnis() egal.

MethodeBeschreibung
eingabe(String kuerzel, String beschriftung)
eingabe(String kuerzel, String beschriftung, String einheit)		 Legt ein Zahlenfeld an. Über das Kürzel wird der Wert in der Formel abgerufen. Kürzel müssen innerhalb einer Karte eindeutig sein.
ergebnis(String beschriftung, Formel formel)
ergebnis(String beschriftung, String einheit, Formel formel)		 Legt ein Ergebnisfeld an. Es darf mehrere geben; alle werden mit einem Klick berechnet.

Formel ist ein funktionales Interface und wird fast immer als Lambda geschrieben:

public interface Formel {
    double berechne(Werte werte);
}

// Verwendung:
ergebnis("Stoffmenge", "mol", w -> w.get("m") / w.get("M"));

Beim Berechnen passiert Folgendes:

  1. Alle Ergebnisfelder werden auf „–“ zurückgesetzt.
  2. Alle Eingaben werden gelesen. Bei einem leeren oder ungültigen Feld bricht die Berechnung mit einer Meldung ab.
  3. Alle Formeln werden ausgewertet. Ist ein Ergebnis unendlich oder NaN (z.B. durch Division durch 0), erscheint „Das Ergebnis ist nicht definiert – wurde durch 0 geteilt?“.
  4. Erst wenn alle Formeln erfolgreich waren, werden die Ergebnisse angezeigt.

Werte hat nur eine Methode: double get(String kuerzel). Ein unbekanntes Kürzel führt zu einer Meldung mit Hinweis auf das fehlende eingabe(...).

Bei Partialdruck, Masse- und Volumenanteil gelten die Einheiten als Vorschlag: Da sich die Einheiten herauskürzen bzw. durchgereicht werden, funktioniert die Rechnung mit jeder einheitlichen Einheit.

Freie Karten

TitrationKarte

  • Abschnitt „Neuer Messpunkt“: zwei Zahlenfelder (Volumen in mL, pH-Wert) und ein Button.
  • Abschnitt „Messpunkte“: Tabelle mit den Spalten Volumen und pH, Button „Alle löschen“.
  • Abschnitt „Titrationskurve“: Diagramm.
  • pH-Werte außerhalb von 0–14 werden mit einer Fehlermeldung abgelehnt.
  • Über messpunkte.beiAenderung(...) wird nach jeder Änderung ein neues Titration-Objekt aus der Tabelle aufgebaut und die Kurve neu gezeichnet. Die Tabelle ist damit die einzige Datenquelle.

AiKarte

  • Textfeld für die Frage, Button „Senden“, Textbereich für die Antwort.
  • Die Anfrage läuft über imHintergrund(...), damit das Fenster bedienbar bleibt.
  • Eine ConnectException (Ollama läuft nicht) wird in die verständliche Meldung „Keine Verbindung zu Ollama – läuft der Dienst? (ollama serve)“ übersetzt.

8Fachlogik

Die Fachklassen enthalten keinen GUI-Code und können unabhängig von der Oberfläche benutzt werden.

Paket Berechnungen

KlasseMethodeFormel
PartialdruckberechnePartialdruck(gesamtDruck, anteil)p = pges · x
MasseanteilberechneMasseanteil(masseKomponente, gesamtMasse)w = mK / mges
VolumenanteilberechneVolumenanteil(volumenKomponente, gesamtVolumen)φ = VK / Vges
molaresVolumenberechneMolaresVolumen(volumen, stoffmenge)Vm = V / n
StoffmengeberechneStoffmenge(masse, molareMasse)n = m / M
molareMasseberechneMolareMasse(masse, stoffmenge)M = m / n

Alle Methoden nehmen und liefern double und prüfen ihre Eingaben nicht; die Prüfung übernimmt die Oberfläche.

Paket Titrationen

Titration speichert eine Messkurve als Liste von double[] {volumen, pH}. addpH(pH, volumen) fügt einen Punkt hinzu (Achtung: pH zuerst), getKurve() liefert die Liste.

Paket APIcalls

modelAdapter.generate(String prompt) schickt eine HTTP-POST-Anfrage an http://localhost:11434/api/generate (Modell cas/teuken-7b-q4km:latest, stream: false) und gibt das Feld response der JSON-Antwort zurück. JSON wird ohne Bibliothek per Zeichenkettensuche gelesen und geschrieben. Der Verbindungs-Timeout beträgt 10 Sekunden. Modell und URL sind Konstanten am Anfang der Klasse.

Paket Konstanten

avogadroKonstante.getWert() liefert NA = 6,02214076 · 10²³ mol⁻¹.

Paket Groesen

groessen.txt listet physikalische Größen im Format Name,Symbol,Einheit1;Einheit2, z.B. Druck,p,Pa;atm;bar;mmHg. GroessenReader ist ein eigenständiges Konsolenprogramm, das die Datei als Tabelle ausgibt. Es ist derzeit nicht in die Oberfläche eingebunden.

9Neue Karte anlegen

Für jede neue Karte sind genau zwei Schritte nötig. Am Paket gui wird nichts geändert.

  1. Neue Klasse in src/karten/ anlegen, die von Formelkarte oder Karte erbt.
  2. In src/karten/Karten.java eine Zeile new MeineKarte(), an der gewünschten Stelle ergänzen.

Beispiel: Formelkarte „Dichte“

Optional zuerst die Formel als Fachklasse in Berechnungen ablegen:

package Berechnungen;

public class Dichte {

    public double berechneDichte(double masse, double volumen) {
        // ρ = m / V
        return masse / volumen;
    }
}

Dann die Karte:

package karten;

import Berechnungen.Dichte;
import gui.Formelkarte;

public class DichteKarte extends Formelkarte {

    public DichteKarte() {
        super("Dichte");
        beschreibung("ρ = m / V");
        eingabe("m", "Masse", "g");
        eingabe("V", "Volumen", "cm³");
        ergebnis("Dichte", "g/cm³",
                w -> new Dichte().berechneDichte(w.get("m"), w.get("V")));
    }
}

Und eintragen:

return List.of(
        ...
        new MolareMasseKarte(),
        new DichteKarte(),      // neu
        new TitrationKarte(),
        ...
);

Beispiel: freie Karte

Wenn das Formel-Muster nicht passt, erbt die Karte direkt von Karte. Bewährt hat sich: Bausteine als Felder speichern, Aktionen als eigene Methoden schreiben und per this::methode übergeben. 

package karten;

import gui.Fehlermeldung;
import gui.Karte;
import gui.Tabelle;
import gui.Zahlenfeld;

public class VerduennungKarte extends Karte {

    private final Zahlenfeld c1;
    private final Zahlenfeld v1;
    private final Zahlenfeld c2;
    private final Tabelle verlauf;

    public VerduennungKarte() {
        super("Verdünnung");
        beschreibung("c₁ · V₁ = c₂ · V₂  –  benötigtes Endvolumen berechnen");

        abschnitt("Eingaben");
        c1 = zahlenfeld("Ausgangskonzentration", "mol/L");
        v1 = zahlenfeld("Ausgangsvolumen", "mL");
        c2 = zahlenfeld("Zielkonzentration", "mol/L");
        button("Berechnen", this::berechnen);

        abschnitt("Bisherige Rechnungen");
        verlauf = tabelle("c₁", "V₁", "c₂", "V₂");
    }

    private void berechnen() {
        double c2Wert = c2.wert();
        if (c2Wert >= c1.wert()) {
            throw new Fehlermeldung("Beim Verdünnen muss die Zielkonzentration kleiner sein.");
        }
        double v2 = c1.wert() * v1.wert() / c2Wert;
        verlauf.zeileHinzufuegen(c1.wert(), v1.wert(), c2Wert, v2);
        info("Endvolumen: " + v2 + " mL");
    }
}

10Fehlerbehandlung

Fehler werden zentral in Karte.ausfuehren() behandelt und unten im Fenster angezeigt. Die Meldung verschwindet nach 6 Sekunden, bei der nächsten Aktion oder per Klick.

ExceptionAnzeigeKonsole
FehlermeldungText unverändertnichts
jede andere Exception„Unerwarteter Fehler: “ + Nachricht (bzw. Klassenname)Stacktrace

Typische Fehlermeldungen, die das Grundgerüst selbst erzeugt:

  • „Bitte einen Wert für „Masse“ eingeben.“: Feld leer
  • „„abc“ ist keine gültige Zahl (Masse).“: Eingabe nicht lesbar
  • „Das Ergebnis ist nicht definiert – wurde durch 0 geteilt?“: Ergebnis unendlich oder NaN
  • „Ungültige Zahl – der alte Wert wurde beibehalten.“: ungültige Eingabe in einer Tabellenzelle
Eigene Prüfungen

In jeder Aktion genügt throw new Fehlermeldung("…"). Ein try/catch ist nicht nötig.

11Zahlenformat

Eingabe

Komma wird vor dem Einlesen durch Punkt ersetzt, danach liest Double.parseDouble die Zahl. Damit funktionieren 12,5, 12.5, 1,5e-3 und 6.022E23. NaN und Infinity werden abgelehnt. Tausendertrennzeichen werden nicht unterstützt.

Ergebnisanzeige

Betrag des ErgebnissesDarstellungBeispiel
0„0“0
0,001 bis unter 1 000 000Dezimalzahl, 6 signifikante Stellen0,213895
sonstwissenschaftlich, 4 signifikante Stellen6,022 · 10²³

Beim Kopieren eines Ergebnisses und in Tabellenzellen wird die Zahl dagegen ungerundet und ohne Exponentenschreibweise ausgegeben, damit sie sich wieder einfügen lässt.

13Build & Konfiguration

.vscode/settings.json (Repository-Wurzel)

Teilt der Java-Erweiterung mit, wo Quellen (Chemierechner/Chemierechner/src) und Ausgabe (…/bin) liegen, bindet alle JARs aus ~/javafx-sdk-25.0.4/lib ein und legt JDK 25 fest.

Wichtig

VS Code liest nur den .vscode-Ordner im geöffneten Ordner. Wird statt der Repository-Wurzel direkt Chemierechner/Chemierechner geöffnet, gilt die dortige, separate Konfiguration.

.vscode/launch.json

Startkonfiguration „Chemierechner - STARTEN“ mit Hauptklasse gui.ChemierechnerApp und den JVM-Argumenten:

--module-path ~/javafx-sdk-25.0.4/lib
--add-modules javafx.controls,javafx.fxml,javafx.graphics,javafx.base,javafx.media,javafx.web
--enable-native-access=javafx.graphics,javafx.media,javafx.web

--module-path und --add-modules sind nötig, weil JavaFX nicht im JDK enthalten ist. --enable-native-access unterdrückt Warnungen neuerer Java-Versionen beim Laden der nativen JavaFX-Bibliotheken.

run.sh

Kompiliert und startet ohne IDE: bin/ löschen → javac → Ressourcen kopieren → java.

.gitignore

bin/ und *.class werden nicht versioniert, weil sie bei jedem Build neu entstehen.

14Bekannte Einschränkungen

BereichEinschränkung
AI-ModusmodelAdapter.extractResponse sucht das Ende der Antwort beim nächsten ". Enthält die Antwort ein maskiertes Anführungszeichen (\"), wird sie dort abgeschnitten. Unicode-Escapes wie ä werden nicht zurückübersetzt.
AI-ModusKein Gesprächsverlauf: Jede Frage wird ohne Kontext der vorherigen gestellt.
FormelkartenEs wird immer in eine Richtung gerechnet; Umstellen nach einer anderen Größe erfordert eine eigene Karte.
FormelkartenKeine Einheitenumrechnung: Die Werte müssen in den angezeigten (bzw. einheitlichen) Einheiten eingegeben werden.
PartialdruckDer Stoffmengenanteil wird nicht auf den Bereich 0–1 geprüft.
TitrationDie Konstruktorparameter von Titration(pH, volumen) werden gespeichert, aber nicht verwendet. Daten gehen beim Beenden verloren (kein Speichern/Laden).
GroesenGroessenReader ist nicht in die Oberfläche eingebunden und liest die Datei über einen relativen Pfad, der vom Arbeitsverzeichnis abhängt.
CodeEinige Klassennamen beginnen mit Kleinbuchstaben (molaresVolumen, modelAdapter, …), entgegen der Java-Konvention. Es gibt keine automatisierten Tests.
KonfigurationPfade zu JDK und JavaFX sind fest in den Konfigurationsdateien hinterlegt; auf einem anderen Rechner müssen sie angepasst werden.

15Ausblick

  • Formelkarten, die nach jeder beliebigen Größe auflösen (zwei von drei Werten eingeben)
  • Einheitenauswahl pro Feld, gestützt auf groessen.txt
  • Export der Titrationskurve als Bild oder CSV, Speichern und Laden von Messreihen
  • AI-Modus mit Gesprächsverlauf und robustem JSON-Parsing
  • Weitere Rechner, z.B. Dichte, Konzentration, ideales Gasgesetz, pH-Wert
  • Unit-Tests für die Fachlogik (Berechnungen) und Zahlenformat
